# Shared rules

Apply these rules to every lab. Detailed manuals remain normative. Read affected rules before changing behavior. A reading budget never permits missing requirements or tests.

## Scope and authority

- Read the current request, baseline, lab README and returned selection. Read its note first. Record question, target, user task, adjustment purpose, assumptions and review criteria. Reuse prior answers and authorization. Ask before unresolved behavior changes the result.
- Follow project ownership, location, retention and source-of-truth rules. Keep one lab per question and one current preview. Continue in that lab when mode changes. Preserve unrelated work, source, picks and feedback. Stopping does not authorize deletion.
- Reuse source components, fixtures, assets, routes and tools. Use authorized connections only. Mark inferred values CONFIRM. Use approved or clearly synthetic content. Preserve locale. Do not invent factual names, metrics or claims.
- Saving, choosing and recommending never approve production. Apply outside the lab only with explicit scoped authorization. Verify code deltas. For an image baseline, return values, units and source selection filename.

## Design and tools

- Keep design variations separate from fixtures, viewport and edit scope. Compare the same fixtures. Family edits affect every applicable fixture. Instance overrides require a request. Preserve unrelated overrides and show scope.
- Stock presets restore full state. For independent design switching, use a scoped adapter that preserves fixture and scope. Define Reset context behavior. Save full context.
- Use stable theme/purpose names, descriptions and complete presets. Keep baseline first, then supplied preferred pick, explorations and archive. The first round has no preferred pick without user input. Preserve saved-file identities and requested-again values. Use the requested count; otherwise start with two or three variations. Precise correction can use one state.
- Use actual property domains and precision. Keep token identity. Hide absent-part controls and disabled dependent fields. Preserve partial numeric drafts, native field undo and exact valid values. Report unsupported requested properties.
- Reuse unchanged bundled runtime. Product tokens govern preview; --b-* tokens govern tools. Small scope, React, deadlines or green product tests do not permit custom panels. Only an explicit user tool-design request can change this boundary; verify the replacement separately.
- Overlay nonmodal tools. Preserve product geometry, wrapping, theme, scroll and selection. Keep focus, target, menus and footer reachable. Keep panel scroll independent. Light/Dark changes tools only. Use separate adapters for missing capabilities. Follow the full integration contract below.

## Continue and verify

- Keep README as question/history/status source; copy relevant fields to About. Use r<round>.<revision>. On returned feedback, record its filename, increase round and reset revision to zero. Increase revision for control, option or preset changes. Keep history oldest first and review status separate from saved status unapproved.
- Export only declared design values and deliberate review notes. Use synthetic fixture IDs and a relative selection fragment. Never export stores, profiles, DOM, credentials or chat history. Include the fixture manifest. Preserve stable lab ID and compatibility; keep keys or test migration.
- Preserve session undo, individual restore, global Reset, native editing and conditional import-note recovery. Load the recovery contract before changing these behaviors. Reuse their tested implementation for routine edits.
- Before handoff, run all applicable source, rendered, control, fixture, recovery and saved-state checks in verification.md. Report source integration, panel conformity and product behavior separately. A state test is not visual evidence. Record gaps; do not claim pixel-perfect or fully applied without evidence.
- Share lab folder plus saved selection, not a local address alone. Report exact file links, verified preview/server requirement, checks, limits and next decision.
